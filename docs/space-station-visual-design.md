# Conceptual Space Station visual — design and build notes

How the animated space station on the ISHAVASYAM.ORG homepage is designed, built, rendered and delivered, and where it comes from.

## 1. Provenance: original, built from code

The station image is **not a photograph, not a downloaded 3D model and not an AI-generated image**. Every part of it is generated by source code in this repository:

| Part of the image | How it is made | Source |
|---|---|---|
| Station structure | Assembled at run time from simple 3D primitives (cylinders, boxes, lathes, tori) using dimensions in one layout file | `src/station/layout.js`, `src/station/model.js` |
| Surface detail (module fabric, solar cells, radiators, gold foil) | Drawn on a 2D canvas in the browser with a seeded random generator; nothing is downloaded | `src/station/textures.js` |
| Earth, clouds, atmosphere, stars | A single GPU shader: every pixel's view ray is intersected with a mathematical sphere; land and clouds come from noise functions | `src/station/earth.js` |
| Lighting, camera, animation | three.js scene setup | `src/station/index.js` |
| Static images (posters, social preview) | Screenshots of the same scene rendered in a headless browser | `tools/render-posters.mjs`, `tools/render-social.mjs` |

- **When and how:** created for ISHAVASYAM.ORG in September 2026, written as source code in this repository with the help of an AI coding assistant (Claude). No image-generation model was used.
- **The Earth is not a real map.** The continents, coastlines and clouds are invented by the noise functions, so no satellite imagery is involved.
- **Third-party code** (both MIT licensed):
  - three.js 0.186.1, the WebGL rendering library
  - the GLSL simplex-noise function by Ashima Arts / Stefan Gustavson, credited in `earth.js`
- **Third-party assets:** none.

### Why it looks familiar

The overall configuration follows the standard engineering pattern of modular orbital stations:
- a long truss carrying solar wings at each end
- pressurised modules along the flight axis beneath it
- radiators, docking ports, a robotic arm and a communications dish

The ISS uses the same functional pattern, so the image reads as "a space station" at a glance.

The specific architecture and geometry are original and not modelled on any real station. It was deliberately made less ISS-like during design:
- **Truss:** a triangular lattice, where the ISS uses a box-section truss.
- **Solar wings:** four roll-out blanket wings, against the ISS's eight main array wings.
- **Modules:** a single axial module stack with one lateral module and a nadir observation dome.

### Claim safety

The site always labels it **"Conceptual Space Station — Illustrative rendering, not an engineered or built design"**. The dimensions are plausible illustrative values; they are not the output of engineering analysis (mass, power, thermal or structural budgets). Keep that wording wherever the image appears.

## 2. Pipeline overview

```
src/station/layout.js      single source of truth: every dimension, in metres
   │
   ├─► src/station/model.js ──► three.js geometry + materials (textures.js)
   │         │
   │         └─► src/station/index.js  scene · lights · camera · animation · performance
   │                    │
   │                    ├─► npm run build ─► assets/js/station.min.js  (esbuild, tree-shaken three.js)
   │                    │        └─► homepage: assets/js/home.js fades the live canvas in over the poster
   │                    │
   │                    ├─► tools/render-posters.mjs ─► images/station/hero-wide-*, hero-band-* (AVIF + WebP)
   │                    └─► tools/render-social.mjs  ─► images/station/ishavasyam-space-station-og.jpg
   │
```

The live 3D scene, the poster images and the plan-view schematic all come from the same layout constants. Changing one dimension therefore changes all three consistently.

## 3. Coordinate frame and layout

Units are metres. The frame is:
- **+X** runs along the integrated truss.
- **+Y** is zenith (away from Earth).
- **+Z** is the direction of flight, along the module stack.

### Integrated truss
| Property | Value |
|---|---|
| Length | 80 m (±40 m) |
| Cross-section | Equilateral triangle, 3.4 m sides, flat face to zenith, apex to nadir |
| Bay length | 3.4 m (≈24 bays) |
| Height of truss centroid above module axis | 5.4 m |
| Members | 3 longerons (r 0.13 m), triangular frames at every bay (r 0.085 m), alternating diagonals (r 0.065 m) — drawn as one instanced mesh |
| Extras | Internal utility spine, 6 orbital-replacement-unit boxes on the nadir face, a structural adapter down to the core node, two rotary joints feeding the solar wings |

### Pressurised module stack (along Z)
| Element | From → to (Z) | Length | Radius |
|---|---|---|---|
| Service & propulsion module | −23.5 → −14.6 | 8.9 m | 2.0 m |
| Habitation module | −14.6 → −3.1 | 11.5 m | 2.15 m |
| Core node | −3.1 → 3.1 | 6.2 m | 2.35 m |
| Research laboratory module | 3.1 → 15.2 | 12.1 m | 2.15 m |
| Forward docking node | 15.2 → 20.2 | 5.0 m | 1.9 m |
| Systems research module (lateral, along −X from the core node) | X −2.35 → −10.8 | 8.45 m | 1.85 m |
| Observation module (nadir of core node) | — | 3.0 m | 1.45 m, glass dome with 6 ribs |

Module details:
- **Shells:** each is a revolved profile (`LatheGeometry`) with end cones and berthing flanges, and a metal ring wherever two elements meet.
- **Service module:** a tapered aft end, a gold thermal blanket, four thrusters, a main engine and two side equipment bays.
- **Laboratory:** two external experiment pallets.

### Docking and berthing ports
There are five ports. Each has an adapter cylinder, a ring and a cap: dark for docking ports, white for expansion ports.

| Port | Position | Kind |
|---|---|---|
| Forward axial | (0, 0, 20.2) | docking |
| Forward zenith | (0, 1.9, 17.7) | docking |
| Forward nadir | (0, −1.9, 17.7) | docking |
| Core, +X | (2.35, 0, 0) | expansion |
| Side-module end | (−10.8, 0, 0) | expansion |

### Power, thermal and external equipment
| Element | Design |
|---|---|
| Solar wings | 4 roll-out blankets, each 13.6 × 23.5 m, on hubs at X = ±36.4 m, starting 2.8 m from the truss; edge booms, tip spreader bar and root mandrel; silver-grey rear face. The wings rotate about the truss axis to track the Sun |
| Radiators | 2 wings at X = ±17.5 m below the truss, each 3 panels of 3.6 × 5.4 m (0.45 m gaps) running aft, tilted 24° |
| External payload platforms | 3 pallets on the truss zenith face at X = 9.5, −12.5, 25.5 m, each with three instrument boxes and a pointed sensor |
| Robotic arm | Base at X = −5.6 m on the truss; 4 segments through shoulder, elbow and wrist to an end effector, with ball joints |
| Communications | High-gain parabolic dish (r 1.25 m, three feed struts) on a 2.8 m mast at X = 4.4 m, plus two low-gain whip antennas |

Overall envelope: about 86 m across the arrays (X) by about 53 m along the arrays (Z).

## 4. Materials and procedural textures

All materials are physically based (`MeshStandardMaterial`: roughness and metalness), lit by the Sun and an Earth-coloured environment.

| Material | Look | Texture (drawn in `textures.js`) |
|---|---|---|
| Shield (module skin) | Off-white fabric, roughness 0.84 | 512² canvas: tonal blanket patches, stitched seams, handrail hints (seed 11) |
| Node shield | Slightly brighter white | Same texture |
| Solar | Deep blue cells, roughness 0.3, metalness 0.35 | 256×1024 canvas: 8 × 40 cells with per-cell tone variation, bus-bar lines, hinge lines every 5 rows (seed 7) |
| Radiator | White coating | 128×256 canvas: coolant tube lines and a panel border |
| Foil (thermal blanket) | Crinkled gold, metalness 0.85 | 256² canvas: 260 random light/dark facets (seed 3) — the restrained gold accent |
| Metal / dark metal / truss | Grey aluminium tones | Solid colour |
| Glass | Near-black, very smooth | Solid colour (observation dome) |

The textures use a seeded random generator. That makes them identical on every load, so the live canvas matches the pre-rendered poster pixel for pixel.

## 5. Earth, atmosphere and stars (`earth.js`)

The whole background is one full-screen triangle drawn behind the station, in a single fragment shader. For each pixel:

1. **The view ray** is reconstructed from the camera's inverse projection and rotation.
2. **The ray is intersected with a sphere** of radius 6,371 km, seen from 420 km altitude.
   - This gives a geometrically correct horizon dip of about 20° and correct limb curvature, with no texture maps.
3. **If the ray hits Earth**, the pixel gets a surface colour:
   - **Continents:** simplex-noise fBm (6 octaves on the high tier, 4 on medium) with domain warping, thresholded into land, continental shelf and ocean.
   - **Land tone:** mixes vegetation and arid colours.
   - **Clouds:** large weather systems modulated by finer, band-limited detail, drifting slowly, with a warm tint near the terminator.
   - **Sun glint:** a specular highlight on open ocean, with a Fresnel sky reflection.
   - **Aerial perspective:** haze increases toward the horizon, plus a bright limb rim.
4. **If the ray misses Earth**, it computes the closest altitude along the ray and draws the atmospheric glow:
   - three exponential scattering layers
   - a warm band where the limb meets the day/night terminator
   - a sparse star field (hashed cells, ~0.65% lit, one-pixel Gaussian dots, faded near the limb)
5. **Anti-shimmer:** every fine noise band fades out once it gets close to the pixel footprint (`fwidth`), so the surface doesn't flicker near the horizon while the camera drifts.

The output goes through the same ACES tone mapping and sRGB conversion as the station, so the two blend naturally.

## 6. Lighting and rendering (`index.js`)

| Setting | Value |
|---|---|
| Key light | One directional "Sun", warm white (#fff6ea), intensity 3.4, placed high, to the right and slightly behind the camera (a raking light that shows the truss lattice) |
| Shadows | PCF soft shadows; 2048² shadow map (high tier) or 1024² (medium); orthographic shadow camera ±56 m |
| Environment light | A generated gradient sphere, blue-white below the horizon dip and black above with a thin limb band, prefiltered with PMREM at intensity 0.55. This is the Earthshine that lights the underside of the station |
| Tone mapping | ACES Filmic, exposure 1.0, sRGB output |
| Background clear colour | #03040c |
| Antialiasing | MSAA; texture anisotropy 8 where supported |

## 7. Camera and compositions

The camera orbits a point near the station's centre (0, 3.0, −1.5 m) at a fixed azimuth, elevation, distance and roll.

The station is placed in the frame with **projection lens shift** (off-axis projection), not by aiming the camera away. That way the station can sit beside the text on desktop without distorting the horizon.

| Composition | Used for | Reference aspect | Vertical FOV | Lens shift (x, y) | Distance | Azimuth / elevation / roll |
|---|---|---|---|---|---|---|
| `wide` | Desktop hero, station to the right of the text | 3:2 | 36.39° | 0.345, 0.045 | 156 m | 48° / 13.5° / −4.5° |
| `band` | Phones and tablets, station band between text and CTA | 4:3 | 37° | 0.02, 0.08 | 137 m | 48° / 14° / −3.5° |
| `og` | 1200×630 social preview | 1200:630 | 30° | 0.27, 0.06 | 152 m | 48° / 13.5° / −4.5° |

- **Cover fitting:** each composition defines a reference frame that is fitted to its container exactly like CSS `object-fit: cover`.
  - Wider containers keep the horizontal field of view; taller ones keep the vertical.
  - This is why the static poster and the live canvas line up at every screen size.
- **Optical centring (phones):** the phone composition centres the pressurised module stack on the page's centre axis, not the station's bounding box.
  - The solar wings are asymmetric, so bounding-box centring made the station look shifted left.
  - The near wing keeps about a 5% margin from the screen edge.
- **Composition switching:** `wide` applies when the screen is at least 1024 px wide and not taller than 5:4 (`(min-width: 1024px) and (min-aspect-ratio: 5/4)`); everything else uses `band`.
  - The same condition is used in the HTML `<picture>` sources, the CSS and the JavaScript.

## 8. Animation

Everything moves very slowly, to suggest orbit rather than draw attention. Time is in seconds.

| Motion | Formula | Amplitude | Period |
|---|---|---|---|
| Station yaw drift | `sin(t·0.012)·0.07 rad` | ±4.0° | ~8.7 min |
| Station pitch drift | `sin(t·0.009 + 0.6)·0.018 rad` | ±1.0° | ~11.6 min |
| Station roll drift | `sin(t·0.007 + 2.1)·0.012 rad` | ±0.7° | ~15 min |
| Sun direction | rotates about Y by `sin(t·0.006)·0.06 rad` | ±3.4° | ~17 min |
| Solar wings | Rotate about the truss axis every frame to face the Sun (computed in the station's own frame) | follows the Sun | — |
| Camera azimuth / elevation drift | `±1.4°` / `±0.5°` sine drift | small parallax | ~5 min / ~6 min |
| Pointer parallax (desktop mouse only) | up to ±1.6° azimuth, ±0.9° elevation, smoothed 4% per frame | subtle | — |
| Earth rotation | `0.35 + t·0.0011 rad` | continuous | ~95 min per turn (close to a real low-orbit period) |
| Cloud drift | noise offset `t·0.0035` / `t·0.002` | continuous | — |

## 9. Static images: posters and social preview

The live 3D scene is optional. The page is complete with the pre-rendered posters, which are also what search engines, reduced-motion users and low-power devices see.

| Output | Rendered at | Delivered as |
|---|---|---|
| `hero-wide-{1280,1920,2400}` | 1600×1067 at 1.5× (2400 px source), `wide` composition | AVIF (q58) + WebP (q80) |
| `hero-band-{640,960,1200}` | 1200×900, `band` composition | AVIF + WebP |
| `ishavasyam-space-station-og.jpg` | 1200×630, `og` composition with the text overlay from `tools/og.html` | JPEG |

- **How a poster is made:**
  1. `tools/render-posters.mjs` opens `tools/capture.html` in headless Chrome with GPU enabled.
  2. It mounts the scene with `staticFrame: true` at time 0 and screenshots it.
  3. It scales the screenshot with ffmpeg (Lanczos) and encodes it with `cwebp` and `avifenc`.
- **Tools required:** ffmpeg, cwebp and avifenc on the PATH.
- **On the page:** the poster is the LCP image. Only the variant for the current layout is preloaded, and it sits inside a `<picture>` with media conditions that match the compositions.

## 10. Delivery and performance

| Aspect | Design |
|---|---|
| Bundle | `npm run build`: esbuild bundles `src/station` with a tree-shaken three.js into `assets/js/station.min.js` (~554 KiB, ~143 KiB gzip). It is committed, so the site needs no build step on GitHub Pages |
| Loading | `assets/js/home.js` imports the bundle dynamically only if the device qualifies, renders the first frame, then fades the canvas in over the poster (1.8 s) |
| Device eligibility | Skipped entirely for: reduced motion, Save-Data or 2G connections, device memory < 2 GB, fewer than 4 CPU cores, no WebGL2, WebGL "major performance caveat", or software renderers (SwiftShader, llvmpipe) |
| Quality tiers | **High:** pixel ratio ≤ 1.75, 2048² shadows, 6 noise octaves, 60 fps. **Medium** (touch devices, small screens, ≤ 4 cores): pixel ratio ≤ 1.25, 1024² shadows, 4 octaves, 30 fps |
| Adaptive fallback | Every 60 frames, if the average frame time is over 1.6× budget, pixel ratio drops to 1. If it is still too slow, the animation stops and holds the current frame as a still image |
| Pausing | Stops when the hero scrolls off screen (IntersectionObserver) or the tab is hidden |
| Start-up | Shader compilation is asynchronous and initialisation yields to the main thread between steps, to keep input responsive |
| Accessibility | The canvas is `aria-hidden`; the meaning lives in the HTML (heading, caption and the poster's `alt` text) |

## 11. Plan-view schematic

`tools/gen-schematic.mjs` reads the same `layout.js` and writes a top-down engineering drawing into `index.html` as an SVG `<symbol>`.

- **Projection:** SVG x = X, SVG y = −Z, with flight direction up.
- **Subsystem groups:** architecture, power, life support, robotics, avionics and station health. Each is styled through CSS custom properties, so hovering a legend item or a frontier highlights that subsystem without duplicating the drawing.
- **Consistency:** because it shares the layout file, the schematic always matches the 3D station.

## 12. Making changes

1. **Edit the design:**
   - dimensions and positions: `src/station/layout.js`
   - shapes: `model.js`
   - surfaces: `textures.js`
   - Earth: `earth.js`
   - light, camera and motion: `index.js`
2. **Rebuild the bundle:** `npm run build`.
3. **Re-render the static images:** `npm run render:posters` (both compositions, or `--only=wide` / `--only=band`), then `node tools/render-social.mjs`.
4. **Regenerate the schematic:** `node tools/gen-schematic.mjs`, if the layout changed.
5. **Check it:**
   - `npm test`
   - `npm run qa:visual`, and look at the screenshots (phones use `band`, desktops use `wide`)
   - `npm run qa:align` to confirm the phone optical centring still holds

After framing changes, keep poster and live canvas in step. Always re-render the posters from the same composition values rather than editing images by hand.
